## Version Format

Versions follow Semantic Versioning (MAJOR.MINOR.PATCH):
- **MAJOR**: Breaking changes
- **MINOR**: New features (backward compatible)
- **PATCH**: Bug fixes (backward compatible)

## How to Update This Changelog

When preparing a new release:

1. Move items from `[Unreleased]` to a new version section
2. Add the version number and release date
3. Keep items organized by category (Added, Changed, Fixed, etc.)
4. Write clear, user-focused descriptions
5. Link to relevant issues or pull requests when applicable

Example:
```markdown
## [1.1.0] - 2024-03-15

### Added
- New command for quick navigation (#123)
- Support for additional file types

### Fixed
- Memory leak in file watcher (#125)
- Incorrect syntax highlighting in edge cases (#127)
```
